快速开始

  1. 在电脑安装 Android SDK platform-tools，并确认 adb version 可正常输出。
  2. 在 Android 设备开启 Developer options 与 USB debugging。
  3. 使用数据线连接设备，在手机弹窗中选择允许调试。
  4. 打开 AnyDeck，在设备列表选择目标设备，即可进入概览、控制、应用、文件或日志工作区。

macOS 可使用 brew install android-platform-tools scrcpy 准备基础工具；Windows 可使用 Chocolatey 或 Scoop 安装 ADB。

通过 USB 连接 Android 设备

  1. 进入手机“关于手机”，连续点击版本号开启 Developer options。
  2. 在 Developer options 中开启 USB debugging。
  3. 连接数据线并将 USB 用途切换为文件传输或保持默认调试模式。
  4. 接受 RSA debugging authorization；如为个人电脑，可勾选始终允许。

若设备显示 unauthorized，请解锁手机并重新确认授权；显示 offline 时可重新插拔 USB 后刷新。

通过 Wi‑Fi 连接

Android 11+ 推荐使用 Wireless debugging 的 QR code 或 pairing code。电脑与手机需要在同一可互访局域网。

  1. 先在手机打开 Wireless debugging。
  2. 在 AnyDeck 设备管理中选择配对方式，录入 IP、pairing port 与 pairing code，或使用二维码流程。
  3. 配对成功后选择 debugging port 建立连接。

连接超时通常与 VPN、系统 firewall、路由器 AP isolation 或 IP/port 变化有关。

打开投屏并控制设备

从设备行或工作区顶部打开 Mirror window。投屏窗口支持鼠标触控、键盘输入、Back、Home、Power、音量、旋转、截图与独立窗口缩放。

  • 鼠标左键用于点击与拖动。
  • 鼠标右键默认映射为 Android Back。
  • 鼠标中键默认映射为 Android Home。
  • 关闭窗口或断开设备时，AnyDeck 会结束对应会话并回收端口。

使用 iOS AirPlay 无线投屏

macOS 版 AnyDeck 可作为 AirPlay Receiver，接收 iPhone 或 iPad 的无线屏幕镜像，并在独立窗口播放画面与设备音频。

  1. 让 iPhone / iPad 与 Mac 连接同一个可互访的 Wi‑Fi；关闭可能阻断局域网发现的 VPN 或 AP isolation。
  2. 在 AnyDeck 中启动 AirPlay Receiver，并确认页面显示接收名称 AnyDeck-AirPlay。
  3. 在 iPhone / iPad 打开“控制中心”，点击“屏幕镜像”，选择 AnyDeck-AirPlay。
  4. 等待 AnyDeck 打开投屏窗口。结束时回到“屏幕镜像”，点击“停止镜像”。

能力边界：当前 AirPlay Receiver 是仅支持 macOS 的实验性能力，不提供从 Mac 反向控制 iPhone / iPad。HLS、HEVC 与 DRM 保护内容不属于当前兼容范围；连接质量还会受到 Wi‑Fi、路由器隔离和系统版本影响。

将手机视频投到电脑播放

Android 与 HarmonyOS 手机可通过 DLNA，将抖音、哔哩哔哩、小红书、爱奇艺等 App 中支持投屏的视频发送到 AnyDeck 播放窗口。

  1. 让手机与电脑连接同一个可互访的局域网。
  2. 在 AnyDeck 中开启 DLNA 视频接收，并确认电脑端显示接收名称。
  3. 在手机视频 App 的播放页点击“投屏”或 TV 图标。
  4. 在设备列表选择 AnyDeck，电脑端会自动打开或复用播放窗口。

兼容性说明：投屏能力取决于 App 版本、账号、地区、片源协议与 DRM 限制。部分内容可能不提供投屏入口；App 内弹幕不会随视频传输。

统一管理本地模拟器

AnyDeck 会扫描本机已有的 Android AVD、DevEco Emulator 与 Xcode Simulator，在同一个列表中展示平台、系统版本、分辨率、SDK、ABI、内存、存储与运行状态。

  1. 从左侧导航进入“模拟器管理”，选择 Android、HarmonyOS 或 iOS 平台。
  2. 使用名称或规格搜索目标模拟器，并查看配置详情。
  3. 选择模拟器后执行启动、停止、冷启动、刷新或打开配置目录。
  4. 启动失败时点击错误状态，查看并复制有界诊断日志。

边界说明：AnyDeck 管理已由 Android Studio、DevEco Studio 或 Xcode 创建的模拟器，不自动下载 System Image，也不代替对应 IDE 创建新设备。

分析 APK 与已安装应用

应用分析统一展示名称、包名或 Bundle、版本、SDK、ABI、DEBUG 状态与文件信息，并按 Tab 查看组件、权限、Metadata、DEX、签名证书和原生库。

  1. 在应用列表双击目标应用进入详情；macOS 也可通过 Finder 使用 AnyDeck 打开本地 APK。
  2. 先在概要区确认包名、版本、Minimum SDK、Target SDK 与 ABI。
  3. 切换组件、权限、签名和原生库 Tab，使用搜索与复制快速定位信息。
  4. 已安装 Android 应用可继续执行启动、强停、授权或撤销等设备操作；HarmonyOS 使用独立 HDC 分析链路。

边界说明：本地 APK 的权限表示 Manifest 声明，签名页展示包内证书信息，但不等同于完整性验签；设备中应用的授权状态以当前用户和系统回读为准。

使用 AnyDeck 运行控制台

运行控制台用于排查 AnyDeck 桌面 App 自身的问题。它会实时汇总主窗口与投屏等子窗口的运行日志、异常堆栈，以及 ADB / HDC 命令失败，无需连接手机也可打开。

  1. 打开 AnyDeck 的“控制台”独立窗口，查看当前会话的实时日志。
  2. 使用关键词搜索窗口来源、命令或错误内容；打开“仅关键日志”可只看 Warning、Error 与 Fatal。
  3. 按需隐藏设备心跳日志，并开启自动滚动跟随最新记录。
  4. 复现问题后复制相关记录，或使用“导出”保存包含保留历史会话的 .log 诊断文件。
  5. 分享日志前检查其中可能存在的设备标识、本地路径或业务数据。

日志边界：清空控制台只会清理当前显示，不会删除磁盘中的诊断记录。控制台不等同于手机 Logcat，也不会采集未转发到 Dart 的 native stderr 或系统 native crash report。

连接 AI Client 与 AnyDeck MCP Server

AnyDeck 通过 HTTP SSE 提供 22 项 MCP Tools，覆盖设备发现、截图与 UI 操作、应用生命周期、Logcat、Crash、文件传输和受控 Shell。不同平台实际可用工具以当前设备能力为准。

  1. 进入 AnyDeck 的“AI MCP”页面，确认监听地址与端口后启动服务。
  2. 按需启用工具；不需要的写入、卸载、清数据或 Shell 工具保持关闭。
  3. 在 Cursor、Claude Desktop、Cline、Windsurf 或其他 MCP Client 中添加 SSE 地址。
  4. 连接成功后先调用 list_devices，再让 AI 针对明确的设备执行截图、分析或诊断操作。
  5. 在 AnyDeck 审计日志中检查请求参数、耗时、结果和错误。
{
  "mcpServers": {
    "anydeck": {
      "url": "http://127.0.0.1:8765/sse"
    }
  }
}

安全说明：默认仅监听本机地址，并提供工具级开关、高危命令黑名单和调用审计。MCP Client 获得的是实际设备操作能力，只连接可信 Client，并在执行卸载、清数据、文件写入或 Shell 前核对目标设备与参数。

管理应用与文件

应用工作区支持检索、APK 安装、启动、卸载、清除数据、冻结/解冻与导出。文件工作区用于浏览设备存储，并支持上传、下载与删除。

  • 安装 APK：将文件拖入设备窗口或使用安装入口。
  • 批量操作：先进入多选状态，再选择目标应用执行动作。
  • 文件传输：确认设备剩余空间与目标目录权限；系统保护目录通常需要 Root。

使用 Logcat、Terminal 与布局分析

Logcat 适合观察实时系统与 App 日志；Terminal 提供交互式 ADB Shell；布局分析会读取当前界面的 XML hierarchy，并与截图区域关联。

  1. 先确认目标设备，避免日志与命令发往其他连接。
  2. Logcat 使用 package、tag 或关键词缩小范围。
  3. 需要复现崩溃时，先清空无关日志，再执行复现步骤。
  4. 布局抓取为空时，确认页面未使用受保护 Surface，并尝试刷新。

常见连接问题

  • 找不到 ADB：将 platform-tools 加入 PATH，或从 Android SDK 目录执行。
  • 设备未出现：更换支持数据传输的线缆与 USB 端口，随后运行 adb devices 交叉检查。
  • 无线连接被拒绝：确认配对端口与连接端口没有混用，并检查手机 IP 是否变化。
  • 投屏启动失败：确认只有一个有效设备目标、USB/Wi‑Fi 链路稳定，并查看 AnyDeck 本地诊断日志。
  • 仍无法解决：导出诊断信息后，在 GitHub Issues 描述系统版本、设备型号、连接方式与复现步骤。
